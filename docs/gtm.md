# 把工作台推出去：第一性原理推导 + 30 天剧本

> 内部讨论稿 · 2026-11-24 · 对象是把工作台做出来的人，不是外部访客。
> README 里只放浓缩版（第十三节），完整推理在这里。

## 0. 一句话结论

不卖「AI 团队」，卖「**你睡觉的时候它在跑，早上你只按两次按钮**」。

推广的全部工作 = 让这句话被 100 个已经在用编码 agent 的人看到，并且让他在 5 分钟内跑出一个 `done`。

---

## 1. 把「推销」拆到不能再拆

任何一次推销在最小尺度上只有三个变量，而且它们是**相乘**关系：

| 变量 | 含义 | 为 0 时会发生什么 |
|---|---|---|
| 痛得具体 | 他此刻正在忍受的具体损失 | 看完就关掉页面（「挺好的，但我不需要」） |
| 信得过 | 他相信这东西真能干活，尤其是不闯祸 | 收藏，不用（「等成熟了再说」） |
| 换得动 | 切换成本 < 现在的痛 | 下载到一半放弃 |

三个变量里，**「痛得具体」最容易被做错**：抽象痛点（效率低、协作乱）不会产生任何动作。
具体的痛长这样：「周五晚上 11 点，agent 说改好了，我在读 300 行 diff，还不敢合。」

---

## 2. 由此推出的六个判断

1. **定位不是「多智能体编排平台」（要教育），是「code review 的收件箱」**。
   人已经被 GitHub / GitLab 的 PR 队列教育过十年，不需要再学一个新概念。
   你的产品在他脑子里的位置应该是：又一个待办队列，只不过里面的东西是 AI 干完的活。

2. **买家是个人，不是团队**。
   他已经在为 Claude Code / Codex / Cursor / opencode 付费，工作台不是替代它们，
   而是「把它们后台跑出来的东西变成可裁决的卡片」。这条线 bottom-up 成立，不需要 CTO 批准。
   团队销售是第二幕，不是第一幕。

3. **竞争不是 Cursor，是「没有」**。
   他现在的替代方案是「自己盯着 agent 跑」——这是最贵的方案（人肉轮询），也是最常见的方案。
   所以文案要打在：**agent 在跑的时候，你在干嘛？**

4. **信任靠可复现的失败，不靠成功截图**。
   人对「自动写代码」默认不信任。成功案例谁都能写，能证明的是「它会抓错」。
   本仓库已经有的素材：故意注入同义反复测试 → 第 1 轮抓出并打回 → 第 2 轮才过；
   `kill -9` 后 3 秒自愈不留孤儿；六断言（离仓可运行 / 工作区正确 / worker 真跑 / SIGTERM 干净 / 无孤儿 / 崩了自愈）。
   这些不是测试报告，是销售材料。

5. **开源 + 本地优先不是理想主义，是转化率的必要条件**。
   数据在他自己的盘上、token 用他自己的 key、没有订阅——试用的心理成本≈0。
   任何「先注册账号再试用」的设计都会把这条最大的优势抵消掉。

6. **一次只有一个人能改变决定：他自己**。
   所以不要做「预约演示」，要做「现在就能跑」。所有落地页 CTA 都应该是同一条：下载 / 一行命令。

---

## 3. 谁最该第一个用（画像要窄）

三个条件**同时**满足才算目标用户：

- 每周至少 3 次让 agent 改代码（有 Claude Code / Codex / Cursor / opencode 任一）。
- 交付物是「能跑 + 能测」的代码，不是设计稿、不是 PPT、不是数据分析。
- 他自己的时间自己说了算（独立开发者、小团队技术负责人、接私活/外包）。

**先别推给**：

| 人群 | 为什么现在不适合 |
|---|---|
| 没有测试的团队 | 护栏的回归基线没有东西可比，价值减半 |
| 金融 / 医疗等要合规审计的 | 无 App Sandbox、无公证、无审计日志导出 |
| 只有 Windows / Linux 的机器 | 当前只发 macOS arm64（Web 版可兜底，但要人装 node） |
| 想要「全自动上线」的人 | 产品刻意把合并留给人，这类用户会觉得「没做完」 |

## 4. 三句可以直接抄的钩子

每条都配一张已有截图，不要配 logo：

1. 「**昨晚它在改，今早我只按了两次按钮。**」→ 配 `docs/roles-review.png`（两张待裁决卡片）
2. 「**我故意把测试写成 `assert.equal(add(2,3), add(2,3))`，它第 1 轮自己抓出来打回了。**」→ 配 `docs/activity-shot.png` + `docs/review-diff.png`
3. 「**一单 23 万 token，比我人工 review 一遍便宜。**」→ 配 `docs/cost.svg`（482,743 → 230,630，−52.2%）

第一条打「省时间」，第二条打「信得过」，第三条打「花得起」。三条对应 §1 的三个变量，缺哪条补哪条。

## 5. 渠道：按「信任传递效率」排序

| 顺位 | 渠道 | 为什么 | 钩子素材 |
|---|---|---|---|
| 1 | 仓库本身（README + Release） | self-host 工具 80% 的转化发生在 GitHub 页面上，且是零成本的常驻广告牌 | 11 张图 / 六断言 / 四张实测表已经就绪 |
| 2 | Hacker News（Show HN） | 人群完全重合，且偏爱「真数字 + 也写失败」的帖子 | 6 单混跑 2,903,602 token / 755 秒 / 一次确定性降级 |
| 3 | r/ClaudeAI、r/LocalLLaMA | 已经在用 agent 的人聚集，接受「本地优先」叙事 | 本地账本 + 自带 key |
| 4 | 中文圈：V2EX / 即刻 / 少数派 / 小红书 | macOS 工具向 + 「AI 帮我写代码」话题天然有流量 | 90 秒屏录 |
| 5 | 定向私信 20 个在 X 上公开晒 agent workflow 的人 | 转化率最高的冷启动方式，但要一条一条写 | 「你那条流水线缺一个 review 收件箱」 |

**不建议**：付费投放（客单低、人群窄、算不过账）、Product Hunt（一次性流量，次日留存差）、
「AI 工具导航站」（流量便宜但用户不做 self-host）。

## 6. 定价（第一性原理：按被替代的人时收，不按 token 收）

| 层 | 价格 | 理由 |
|---|---|---|
| 自托管（当前形态） | 免费，MIT | 用户自带模型 key，我们没有边际成本；免费是转化率的必要条件 |
| 团队版（多人 + 远程访问 + 审计导出） | 按席位，约 $15~25 / 席位 / 月 | 锚点是「一个席位 ≈ 每月省下 X 小时 review」，不是「比竞品便宜」 |
| 企业内网部署 + 支持 | 年费，按项目 | 卖的是「我帮你把它跑在你们的网里」，不是软件 |

**为什么不能按 token 收费**：token 花的是用户自己的 key。对他加价，他会立刻算出来「你在给我的账单加价」，
信任瞬间归零——而信任是这门生意唯一的资产。

## 7. 30 天剧本（每天一件事）

| 天 | 干什么 | 完成判据 |
|---|---|---|
| 1-2 | 修分发摩擦（见 §8），确保别人双击不被 Gatekeeper 拦 | 在一台没装过开发环境的 Mac 上装成功 |
| 3 | 录 90 秒屏：选目录 → 建任务 → 看它跑 → 裁决 → 合并 | 视频无剪辑、无解说也能看懂 |
| 4 | 写实测贴（用已有 6 单混跑数据，失败也写） | 标题用钩子 1 |
| 5 | 同一天发 HN + V2EX + X | 三个渠道同一张图、同一句话 |
| 6-14 | **只做一件事**：帮每个留言的人远程跑通 10 分钟 | 每个留言都有回复，跑通的人 > 50% |
| 15 | 收 5 条「我实际用了」的反馈，写成 case | 每条有一张他自己的截图 |
| 16-30 | 拉 3 个团队试内网部署，谈团队版 | 至少 1 个愿意付钱或给公开评价 |

第 6-14 天是分水岭：大多数开源项目死在这 9 天——发完就等，而真实转化发生在「有人卡住时你出现」的那一刻。

## 8. 三个必须先修的摩擦（都在漏斗前两级）

| 摩擦 | 后果 | 最小成本解法 | 正解 |
|---|---|---|---|
| ad-hoc 签名、无公证 | 下载后被 Gatekeeper 拦，这是漏斗第一级最大流失 | 下载页第一行放 `xattr -dr com.apple.quarantine /Applications/Workbench.app` | Apple Developer ID + 公证（$99/年） |
| 只有 macOS arm64 | 直接砍掉一半潜在用户 | 补一条「不装 app，跑内核 + 浏览器」的 Docker/一行命令（Web 版已具备） | Linux 版内核 + Web 版打包 |
| 真引擎成本不透明 | 用户不敢放手跑，激活失败 | 任务卡片显示「已花 / 上限」，超限自动 blocked（已实现）；首单默认 budget 上限 | 按体量预测花费 |

第一条尤其致命：README 写得再好，Mac 上下载一个未签名 app 被系统拦住，80% 的人会直接放弃。
**这是当前投入产出比最高的一个改动。**

## 9. 漏斗指标（别看下载量）

| 层级 | 指标 | 目标 |
|---|---|---|
| 激活 | 从打开 app 到第一个任务 `done` 的中位时长 | < 10 分钟 |
| 价值 | 每周裁决次数 | ≥ 5 |
| 可信 | 护栏命中率（真抓到问题的比例）、重试后通过率 | 命中率 > 0 才说明有用 |
| 留存 | D7 仍提交过任务的比例 | > 25% |
| 传播 | 主动写文/截图提到它的用户数 | 第一个月 ≥ 3 |

下载量是最容易刷、也最没有信息量的一格。**激活时长**才是这个产品真正的生死线。

## 10. 留给你的四个决定（这就是要讨论的部分）

1. **前 10 个用户从哪来**：自己的圈子（快、留存高、样本小）还是公开渠道（慢、样本大、要准备好被挑刺）？
   公开渠道的前提是「90 秒视频 + 一个真实失败故事」，两者都还没有。
2. **主打中文还是英文**：英文市场大 10 倍、竞争也大 10 倍；中文侧的「agent 后台执行 + 人只 review」叙事目前几乎没人占位。
3. **要不要做云托管**（打开网页就能用，5 分钟出结果）：能救激活率，但会破坏「数据在你盘上、key 是你的」这条最大差异。
   折中方案：只托管「演示仓库」，真任务必须自托管。
4. **许可**：MIT 现在意味着大厂可以白嫖（改名就可卖）。要不要换 AGPL，或者核心开源 / 团队版闭源的双许可？

我的倾向（供反驳）：先做 1 和 2 的「中文 + 自己的圈子」，因为实测数字和失败案例都是中文语料，
而英文侧的对比对象是 Cursor/Devin，教育成本高得多；3 先不做，4 保持 MIT（这个阶段传播 > 保护）。
